# Agent playbook: Vastlands

Read [DESIGN.md](DESIGN.md) for what the game is and
[docs/AGENTIC_PIPELINE.md](docs/AGENTIC_PIPELINE.md) for how it's produced.

## Rules of the world (don't break these)

- **Nothing heals on its own.** No passive regeneration of terrain, structures or vehicles.
  Repair only happens through a player action (Repair pack beam), and rebuilding blown-out panels costs materiel.
- **Terrain changes are permanent:** craters, graded roads, causeways.
- **Content is data.** New levels go in `content/levels/*.json`. Don't hard-code maps in TypeScript.
- Tuning numbers live in `src/config.ts`.

## Commands (run from `web/`)

| Command | Use |
|---|---|
| `npm run dev` | Dev server (http://localhost:5173) |
| `npx tsc --noEmit` | Typecheck (includes `scripts/`) |
| `npm run validate` | Validate all levels |
| `npm run playtest -- <id\|all> [--minutes N] [--seed N] [--json]` | Headless bot matches with quality gates; exits 1 on failure |
| `npm run assets -- help` | Asset toolchain: motions (generate/analyze/vectors/BVH import), texture baking, character build + GLB |
| `npm run assets:check` | Skeleton + motion analysis + character budgets |
| `npm run check` | Everything above (typecheck + validate + asset checks + 8-minute playtests on two seeds); run before finishing any change |

## Adding a level

1. Create `content/levels/<kebab-id>.json` (see the `LevelDef` type in `src/content/level.ts`). Required fields:
   `id, name, author, description, biome, seed`. Optional fields: `teamSize, captureLimit, startMateriel,
   tags, overrides, bases, deposits`.
2. `npm run validate`, then `npm run playtest -- <id> --minutes 10`. All gates must pass. Try two
   or three `--seed` values, because bots are stochastic.
3. Look at it: `npm run dev`, pick it in the menu, or in the console run
   `startMatch({ biome, seed, teamSize, level })`.

## Characters, motions, textures

See [docs/CHARACTER_TOOLCHAIN.md](docs/CHARACTER_TOOLCHAIN.md). Short version:
- Motions are JSON (`content/motions`), generated by `npm run assets -- motion gen <preset> --<param> v`.
  `motion analyze` must report ✓ (no foot slide, no penetration, clean loop).
- Characters are JSON (`content/characters`): volumes, bulk and armor pieces on bones. `character build` must pass budgets.
- Materials are layer stacks (`content/materials`). Painted strokes are layers too, so commit them as data.
- Visual check: `/workbench.html`. Drive it with `window.workbench` and use `screenshot()` for visual QA.
- Never commit `public/generated/`; it's rebuilt from `content/`.

## Self-improving graphics

See [docs/SELF_IMPROVING_GRAPHICS.md](docs/SELF_IMPROVING_GRAPHICS.md).
- `motion compare`, `motion fit` and `texture compare` measure ours against references, and `bench` tracks scores over time.
- `web/reference/` is **local-only and gitignored**. Never copy original Tribes data (or keyframes derived from it)
  into `content/`, the build, or commits. Use `--adopt` only for high-level fitted parameters, and only after a human decides.

## Levels' expected pace

`expect.flagGrabsPer5Min` in a level sets the playtest's flag-pressure gate (default 0.9).
Siege and economy maps may declare a slower pace, but justify it in the PR.

## Changing gameplay

- After any change to physics, weapons, AI or economy, run `npm run playtest -- all --minutes 10`
  and compare `stats` (`--json`) before and after. Say in the PR what moved.
- Bot changes are the most fragile. Watch the **mobility** and **flag-pressure** gates.
- Debug in the browser: `window.game` is the live game. `game.frame(1/60)` in a loop fast-forwards
  the simulation.
